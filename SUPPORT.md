# Support

## Asking a question

Open a [GitHub issue](../../issues) and add the `question` label. There's no
separate discussion forum — Issues is the single place to ask.

## What to expect

This is a single-maintainer project, worked on outside a main job. Issues
and PRs are triaged **best-effort, with no fixed response-time SLA**. That's
stated honestly here rather than promising a number that could get broken
during a busy or inactive stretch.

## Not sure where to ask?

- **Reporting a security vulnerability?** Don't open a public issue — see
  [SECURITY.md](SECURITY.md) for the private disclosure process instead.
- **Want to contribute code?** See [CONTRIBUTING.md](CONTRIBUTING.md) for
  dev setup and the PR flow — that's a different question from "I need
  help using this," which is what this file covers.
